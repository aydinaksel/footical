# Claude Context

## leptos_router Quirks

- `leptos_router` has no `csr` feature — do not add `features = ["csr"]` in
  Cargo.toml or the build will fail
- The `A` component does not accept a `class` prop — use `use_location()` from
  `leptos_router::hooks` to detect the active route and apply classes to inner
  elements instead

## Deployment

GitHub Actions builds on push to main and deploys `dist/` to Cloudflare Pages.
Required GitHub secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
The first workflow run creates the Pages project; subsequent runs skip that step
silently via `continue-on-error: true`.

## Data Pipeline — Next Steps

The static JSON files in `static/` and iCal files will be generated by a Rust binary running
on Zeus (the home server) via a systemd timer, and uploaded to Cloudflare R2.

### Architecture

```
systemd timer on Zeus (daily)
  → Rust generator binary
      → query Postgres (local Docker network)
      → generate JSON + iCal files
      → upload to R2 via S3-compatible API
```

- **R2 bucket**: `footical-data`
- **Custom domain**: `data.footical.club` (attached in Cloudflare dashboard)
- **CORS**: allow GET from `https://footical.club`
- **Leptos app**: fetch JSON from `https://data.footical.club/` instead of relative paths

### R2 Upload

R2 exposes an S3-compatible endpoint: `https://<account_id>.r2.cloudflarestorage.com`.
Use the `aws-sdk-s3` crate in the generator binary, pointed at that endpoint.
Create a dedicated R2 API token scoped to the `footical-data` bucket only (not the full
Cloudflare API token). Store credentials on Zeus, e.g. `/etc/footical/env`.

### Workspace Structure (done)

- `app/` — Leptos CSR WASM binary (`footical-app`)
